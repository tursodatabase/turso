# ATTACH DATABASE

The ATTACH DATABASE statement adds another database file to the current connection under a schema name. Once attached, tables in the external database can be queried alongside tables in the main database.

## Syntax

```sql
ATTACH [DATABASE] filename AS schema-name;
```

## Description

ATTACH opens the database file at `filename` and makes its tables accessible through the given `schema-name`. Tables in the attached database are referenced as `schema-name.table-name`.

### Clauses

| Clause | Description |
|--------|-------------|
| `DATABASE` | Optional keyword. Has no effect on behavior. |
| `filename` | A string expression that evaluates to the path of the database file to attach. Use `':memory:'` to attach an in-memory database. |
| `schema-name` | The name used to qualify table references from the attached database. This name must be unique among all attached databases on the connection. |

Every connection has a built-in schema named `main` for its primary database. The names `main` and `temp` are reserved and cannot be used as schema names for attached databases.

<Info>
This feature is experimental and must be [enabled before use](/docs/sql-reference/experimental-features). Attached databases support both read and write operations (INSERT, UPDATE, DELETE, CREATE TABLE, etc.). The attached database's journal mode must match the main database's journal mode (e.g., both WAL or both MVCC).
</Info>

## Examples

### Attach and Query an External Database

```sql
-- Attach another database file
ATTACH DATABASE 'archive.db' AS archive;

-- Query a table in the attached database
SELECT * FROM archive.events WHERE event_date > '2025-01-01';
```

### Cross-Database Queries

```sql
ATTACH 'customers.db' AS customers_db;

-- Join tables across the main and attached databases
SELECT o.id, o.total, c.name
FROM main.orders o
JOIN customers_db.customers c ON o.customer_id = c.id;
```

### Attach an In-Memory Database

```sql
ATTACH ':memory:' AS scratch;
```

### Attach an Encrypted Database

The main and attached databases select encryption independently: either can be plaintext or encrypted. Supply the attached database's own credentials in its URI:

```sql
ATTACH 'file:encrypted.db?cipher=aegis256&hexkey=YOUR_HEX_KEY' AS encrypted;
```

Non-NULL `ATTACH ... KEY` values are rejected before the target is opened. Use the URI parameters above to configure encryption. `KEY NULL` is accepted.

While a database of the connection is encrypted, the connection encrypts its temporary files on disk. The TEMP database chooses its encryption when it is created. If the TEMP database is an unencrypted file that holds no objects and no rows in `sqlite_sequence` or `sqlite_stat1`, and its `user_version` and `application_id` are 0, ATTACH of an encrypted database drops it, and its next use creates it again, encrypted, with the same page size. If the unencrypted TEMP database holds objects or such rows, has a `user_version` or `application_id` that is not 0, or a transaction uses it, ATTACH of an encrypted database is rejected before the target is opened. Drop the TEMP objects, delete the rows, and set these values to 0 first, or attach the encrypted database before you use TEMP. See [Encryption](/docs/sql-reference/pragmas#encryption).
