General information

solidDB Accelerator library (known also by the feature name of Linked Library Access) is a part of the solidDB product, that allows accessing a database from inside a client process, avoiding overhead and latencies of inter-process or network communication. Using the Accelerator library is especially efficient with solidDB memory-resident tables when transaction response times reach the minimum.

The information below is intended to describe how to run TATP benchmark with solidDB Accelerator in Linux environment.

Using solidDB Accelerator with UnixODBC

UnixODBC Driver Manager allows using any available ODBC Data Source as configured at run-time. solidDB Accelerator can also be used that way because it exposes the same Application Programming Interface (API) as any ODBC driver.

The following configuration files must be set up to use solidDB Accelerator with UnixODBC:

  • odbcinst.ini
  • odbc.ini (.odbc.ini)
  • solid.ini

odbcinst.ini

solidDB Accelerator must be registered in UnixODBC as a ODBC Driver in odbcinst.ini file. That file is usually system-wide and is located in /etc directory. The section similar to the following must be added: 

[Solid Accelerator]
Driver=/opt/SolidDB/soliddb-6.3/bin/ssolidac63.so
Threading=0

odbc.ini (.odbc.ini)

An ODBC Data Source must be created specifying solidDB Accelerator driver registered in the previous step. The file used for the purpose is either system-wide /etc/odbc.ini or user-specific $HOME/.odbc.ini, both having the same syntax. The example of modifications is provided below: 

[MyAcceleratorDB]
Driver=Solid Accelerator

In this example, the driver is named 'Solid Accelerator' and the absolute path to Accelerator shared library binary (ssolidac63.so) is specified.

solid.ini

solid.ini in the described accelerator configuration contains both the client-side and server-side settings. The client configuration describes that the ODBC data source is Solid Accelerator and is given in [Data Sources] section and must use the reserved word 'localserver' as a data source string. The server-side configuration can be any valid solidDB server configuration.

We provide a simple example with memory-based tables and no logging below: 

[Data Sources]
MyAcceleratorDB="localserver"

[General]
DefaultStoreIsMemory=Yes

[IndexFile]
FileSpec_1=solid.db 16000m

[Logging]
LogEnabled=no

Linking and using solidDB Accelerator directly

Instead of linking to unixODBC, TATP benchmark can be also linked to solidDB Accelerator library directly. Direct linked binaries do not require installed ODBC Driver Manager and setting up ODBC configuration. Directly linked binaries also result in better performance because no intermediary layer like driver manager is involved.

See Makefile for instructions on how to build TATP directly linked with solidDB Accelerator library.

Accessing solidDB Accelerator database from TATP test

No additional client settings are needed as compared to UnixODBC configuration. However, solid.ini file must still be used for solidDB server-side settings.

Local Accelerator database is accessed if 'localserver' is specified in the DDF file:

db_connect="DSN=localserver;UID=dba;PWD=dba"

Avoiding extra database start

By default, TATP connects to a test database several times. One connection is performed to apply the test load. In addition to that, other connections are established for the control program to check and update the database state. These additional steps are necessary if TATP runs for the first time on a not yet configured database, or checks whether the database population size have changed since the previous run.

Additional database connections inflict database startup and may take time, especially if memory-based tables are used. Those extra connections may be skipped if the test database is correctly initialized and populated, with the following configuration modifications:

  • 'TargetDBInit' parameter in tatp.ini must not exist (or be commented out) or should contain an empty value
  • 'populate' line must not exist (or be commented out) under [Test sequence] section in TDF file
